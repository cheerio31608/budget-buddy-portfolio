# 개발 의사결정과 트러블슈팅 기록

이 문서는 기능 구현 중 고민한 대안과 선택 이유를 면접에서 설명할 수 있도록 기록합니다. 코드나 문서의 다른 설명과 충돌하면 실제 구현을 우선 확인합니다.

## CSV를 한 번의 업로드로 분석하기

### 문제

은행·카드사·개인 가계부 파일은 컬럼명이 조금씩 다릅니다. 매번 날짜, 금액, 카테고리 등을 사용자가 연결해야 한다면 분석 체험이 번거롭지만, 의미가 다른 컬럼을 잘못 연결하면 소비 통계도 잘못됩니다.

### 선택

- 자주 쓰이는 한국어·영어 헤더는 별칭 목록으로 자동 연결합니다.
- 날짜·금액·수입/지출 헤더가 다르더라도 샘플 값이 일관되고 후보 컬럼이 하나뿐일 때만 보조 추론합니다.
- 숫자 컬럼처럼 둘 이상의 후보가 있거나 필수 컬럼을 찾지 못하면 자동으로 단정하지 않고 사용자 확인을 요청합니다.
- 직접 컬럼을 연결해 분석한 경우, 다음 업로드에서 재사용할 수 있도록 헤더 구성과 매핑만 브라우저에 저장합니다. 거래 행이나 인증정보는 저장하지 않습니다.
- 자동 분석은 임시 분석입니다. 실제 거래 가져오기는 미리보기와 검증 후 별도 확인을 요구합니다.

### 트레이드오프와 다음 단계

헤더 별칭과 값 패턴은 가볍고 설명 가능하지만, 모든 금융기관의 파일 형식을 알아낼 수는 없습니다. 특히 수입/지출 값이 없거나 의미가 불분명한 금액 컬럼은 사용자 확인이 필요합니다. 거래에 카테고리가 없는 경우 상호명으로 카테고리를 제안하는 기능은 별도 문제입니다. 오분류가 후속 통계와 AI 설명에 전파되지 않도록, 향후 추가한다면 확실한 규칙부터 자동 적용하고 불확실한 분류는 사용자가 수정할 수 있는 제안으로 다루는 것이 안전합니다.

은행 계정 직접 연결과 자동 동기화는 외부 사업자별 인증·동의·토큰 보호·장애 대응이 필요하므로 개인 포트폴리오의 첫 범위에는 포함하지 않습니다. CSV 입력과 공통 분석 모델을 먼저 안정화하고, 실제 필요가 생기면 제공자별 데이터 어댑터를 검토합니다.

## Docker Compose로 PostgreSQL 개발환경 재현

### 문제

개발자마다 로컬 PostgreSQL 설치 여부, 버전, 포트, 계정 설정이 다르면 “내 컴퓨터에서는 되는데 다른 환경에서는 안 되는” 문제가 생기기 쉽습니다. 설치 과정을 README에 여러 개의 동등한 경로로 안내하면 처음 실행하는 사람도 선택에 어려움을 겪습니다.

### 선택

- Docker 이미지는 PostgreSQL 실행에 필요한 파일과 설정을 묶은 실행 단위입니다.
- Docker Compose는 프로젝트의 PostgreSQL과 Spring Boot 백엔드 실행 설정을 한 파일에 선언해 함께 올릴 수 있게 합니다.
- 저장소에서는 Compose를 권장 시작 경로로 안내하고, Frontend 개발 서버는 별도 실행합니다. H2는 테스트에 사용하고, 로컬에 직접 설치한 PostgreSQL 연결은 필요할 때의 대안으로 둡니다.
- PostgreSQL 데이터는 named volume에 저장하므로 컨테이너를 정지해도 데이터가 보존됩니다. 데이터 삭제가 필요한 별도의 요청이 없으면 volume 삭제 명령을 사용하지 않습니다.

### 트러블슈팅에서 설명할 점

Docker Desktop은 컨테이너를 관리하는 앱이고, 실제 Backend·DB는 컨테이너로 실행됩니다. Docker Desktop 창을 닫는 것과 특정 컨테이너를 정상 중지하는 것은 같은 조작이 아닙니다. Compose에서 `app`만 중지하면 프론트엔드 개발 서버나 PostgreSQL은 계속 실행될 수 있으므로 각 실행 프로세스를 구분해 확인해야 합니다. Windows에서 가상화/WSL2 지원이 준비되지 않았을 때 Docker 엔진이 시작하지 않는 문제도 코드 문제와 환경 문제를 나누어 진단해야 합니다.

## 포트폴리오 설명 포인트

> CSV를 무조건 추측하게 만들기보다, 확실한 헤더와 값 패턴만 자동 연결하고 애매한 경우에만 확인을 요청했습니다. 분석 체험은 자동화하되 데이터 저장은 별도 사용자 확인으로 분리해 편의성과 정합성을 함께 고려했습니다. 개발환경은 Compose로 PostgreSQL과 Backend의 실행 조건을 재현 가능하게 만들고, H2 테스트와 로컬 직접 실행은 대안으로 구분했습니다.
